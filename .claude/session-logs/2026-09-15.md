## Phase 1 — Auth + PIN (in progress)
- Installed Drizzle ORM + `pg` + `drizzle-kit`; set up `drizzle.config.ts` and `db/client.ts`.
- Wrote `families`/`parents` schema (user-authored, coached) — caught and fixed three issues along the way: `pin_locked_until` wrongly `.notNull().defaultNow()` (should be nullable — null means "not locked out"), a typo (`pinAttemps`), and camelCase column-name strings (should be snake_case; JS property names stay camelCase).
- Generated + applied the migration against local dev Postgres (Docker Desktop needed a restart mid-session); confirmed the resulting tables with `psql` match the schema exactly, including the FK cascade.
- Wrote `db/migrate.ts` (runs automatically before `index.ts`'s `app.listen`).
- Set up Prettier + format-on-save (`.prettierrc`, `.vscode/settings.json`), matching `meal-planner`'s config.
- Shared zod schemas (`SignupInputSchema`, `LoginInputSchema`) — added a `.refine()` enforcing exactly one of `familyName`/`inviteCode`. Caught a real bug: the first `.refine()` call was a bare statement whose return value was discarded (zod schemas are immutable, so it never took effect) — fixed by chaining it directly into the assignment. Verified all 5 combinations (familyName-only, inviteCode-only, both, neither, empty-string edge case) against the real schema with `safeParse`.
- Built `authService.signup()` step by step, catching several real bugs along the way:
  - `String(input).toLowerCase()` instead of `input.email.toLowerCase()`.
  - Missing `await` on the Drizzle select (checking a Promise against `null` instead of an array's `.length`).
  - Backwards control flow — `throw` placed after the `if` block instead of inside it, so `EMAIL_TAKEN` fired unconditionally on every signup.
  - Missing `await` on `bcrypt.hash()` (`Promise<string>` where the DB column wanted `string`) — TypeScript caught this one directly.
  - `JWT_SECRET` guard clause living inside `signup()` instead of hoisted to module scope (duplication risk once `login()` needs it too); then a TypeScript narrowing gotcha — a module-level `if (!JWT_SECRET) throw` doesn't narrow the type inside a separately-declared function, so an explicit `as string` assertion was needed at the declaration site.
  - Forgot to `export` `signup` — nothing outside the file could import it yet.
- `signup()` verified end-to-end against the real database: successful signup, correct family+parent rows linked via FK, mixed-case duplicate-email correctly rejected, test rows cleaned up (cascade delete confirmed working).
- `authService.login()` — not started, planned for next session (select by email, `bcrypt.compare`, same JWT-issuing pattern, same generic `INVALID_CREDENTIALS` error for both "no such email" and "wrong password").
